# AHE 变更策略

用本策略避免不必要的全量运行，同时保住 AHE 结果的有效性。每个候选变更在
动手前先定级。等级描述的是支撑结论所需的证据，不是代码重要与否。

## A 类：无需端到端 AHE 试验

这些变更不改变执行、模型输入、候选生成、评测或证据语义：

- 注释、文档、示例与报告措辞；
- 纯格式化且不改变生成运行时产物；
- 只读取既有 trace 并产出报告的分析代码；
- 不被线上 evaluator 加载的测试 fixture；
- 字节等价的确定性重命名/重排（生成的命令或 manifest 完全一致）。

适用时跑一次格式化或解析检查。不要从 A 类变更宣称 AHE 性能收益。

## B 类：定向验证，默认不需要 holdout

这些变更影响有界的辅助或可观测路径，但以保持行为为目的：

- 追加式 trace 字段、候选 ID、计时跨度或 debugger 产物路径；
- 不改变 evaluator 数值的日志/指标 schema 适配；
- 基于归档 fixture 测试过的纯解析器、压缩器或上下文投影；
- 只在失败时恢复原始行为的错误处理；
- 带精确回放测试的动作融合或 observation 打包辅助。

跑语法/类型检查、聚焦单测与回放或冒烟 evaluator。对比前后原始
stdout/stderr 与指标。若辅助变更改变了 prompt 内容、工具顺序、重试行为、
校验或候选选择，升级为 C 类。

## C 类：需要 dev 与 holdout

这些变更可能改变任务结果或资源使用，因此需要固定 dev 运行加独立
holdout 运行：

- agent prompt、系统指令、模型路由、工具策略、工具描述或停止条件；
- memory 读写策略、中间件、上下文压缩、压缩器、缓存或 prompt 前缀变更；
- worker 分发、并行度、重试、超时、调度器、verifier、gate、debugger 或
  续跑行为；
- 候选提案、变异、接受、晋级或空提案/平台期策略；
- adapter 行为、可变文件映射、环境装配或任务专属 kernel 变更；
- 改变 token、时延、模型调用、工具调用、迭代数、通过率、准确率或性能
  指标的变更。

先跑校验，再跑 dev 与 holdout。保留 baseline 候选，质量与资源指标分开
对比。靠跳过校验、隐藏失败、改动任务数据或削弱质量门禁换来的加速无效。

## F 类：冻结基础；不为 harness 实验修改

除任务明确说明 evaluator 本身就是优化目标外，以下都按实验合同对待：

- 任务集、golden 数据、evaluator 实现、runner、`eval-cmd`、holdout 命令
  与分数解析器；
- 正确性阈值、通过/失败语义、主指标定义与独立 accuracy/F1 检查；
- 已声明的可变文件白名单与候选 workspace 隔离；
- 硬件/软件环境、依赖锁定、模型/provider 身份、种子策略与时间预算；
- 原始 trace/evidence 保留、产物路径、回执 ID 与用于对比的源 checkout；
- `baseline-memory.json` 中已审阅的基线记忆与历史结论文档。

若其中之一必须改变，用新的 baseline ID 开启新实验族。不要把其分数或收敛
曲线与旧族直接对比。

## 基线记忆协议

`baseline-memory.json` 是只读先验。它记录反复出现的模式与安全默认动作；
它不是实时草稿，绝不能因一次意外运行就重写。新观测放进运行报告或单独的
带日期导出。只有一批经审阅的运行确认模式后才更新记忆，并以新版本/日期
保留旧记忆。

动手前先回答：

1. 哪些基线合同字段是冻结的？
2. 是哪条历史模式触发了本次变更？
3. 什么不变量必须保持成立？
4. 该等级允许的最小验证级别是什么？
5. 什么证据会促进、拒绝或重新定级该变更？
